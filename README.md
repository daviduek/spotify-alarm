# Wake

> A reliable alarm clock with intelligent audio sources — Spotify, your own voice, or a simple alarm.
> **The alarm must always wake you up. Spotify makes it better, but never makes it less reliable.**

Working title: *Wake*. Monorepo for the iOS/Android app (React Native + Expo, native alarm engines in Swift/Kotlin),
the shared domain package and the marketing/legal website (Next.js on Vercel).

**Status: Phase 0 — technical validation.** The code builds and type-checks; native behaviour must be confirmed on
physical devices before the product UI is built. See [`docs/TECHNICAL_VALIDATION.md`](docs/TECHNICAL_VALIDATION.md)
and [`docs/SETUP.md`](docs/SETUP.md) (what the project owner must set up: Vercel, EAS, Spotify Dashboard, devices).

## Quick start

```bash
npm ci                    # installs every workspace (Node 22)
npm run check             # typecheck all workspaces + domain unit tests
npm run web               # Next.js dev server for apps/web
```

Mobile needs a **development build** (native modules ⇒ no Expo Go):

```bash
cd apps/mobile
cp .env.example .env      # add EXPO_PUBLIC_SPOTIFY_CLIENT_ID (optional — alarms work without it)
eas build --platform android --profile development   # or ios (Apple Developer account, iOS 26 device)
npx expo start            # then open the dev build on the device
```

Local native builds (Mac with Xcode 26 / Android Studio): `npx expo prebuild` then `npx expo run:ios` / `run:android`.

## Architecture in one picture

```
             React Native (TypeScript) — UI, state, SQLite, Spotify PKCE + Web API, JS audio engine
                                   │  AlarmScheduler / MusicProvider / AlarmAudioEngine interfaces (@wake/domain)
                                   ▼
                     modules/wake-alarm  (Expo Modules API, TS contract)
                    ┌──────────────┴───────────────┐
        iOS: AlarmKit (system alarm,        Android: AlarmManager.setAlarmClock → AlarmReceiver
        lock-screen alert, bundled sound,   → AlarmService (USAGE_ALARM MediaPlayer, vibration,
        snooze countdown)                   native fade, full-screen AlarmActivity, auto-silence)
                                            → BootReceiver restores after reboot / update / TZ change
```

Fallback rule (spec §11): the native alarm always rings with the bundled fallback sound. Spotify or a recording are
layered on top when the JS layer is alive; every failure path leaves the fallback ringing.

Details: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Decisions and trade-offs: [`docs/DECISIONS.md`](docs/DECISIONS.md).
